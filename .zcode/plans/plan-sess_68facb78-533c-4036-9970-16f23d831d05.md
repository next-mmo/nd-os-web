# Workspace: real-file storage layer for ND OS

## Goal
Replace the localStorage-only data model with a real workspace filesystem. Files saved in ND OS appear as **actual files** on the user's computer (File System Access API, Chromium browsers) and fall back to **persistent browser storage** (IndexedDB) on Firefox/Safari — same app code either way.

## Architecture

### New module: `src/lib/workspace/` (Svelte 5 runes module)
- **`workspace.svelte.ts`** — reactive state + public API. Uses `$state` runes so `workspace.status` / `workspace.backend` reactively update the UI everywhere.
  - State: `status: 'disconnected' | 'connected'`, `backend: 'native' | 'fallback' | null`, root handle (internal).
  - Public API (all path-based, POSIX-style: `/`, `/Documents`, `/Documents/Notes.md`):
    - `connect()` — prompts user to pick a folder (FSA) or initializes IndexedDB store
    - `disconnect()` — forgets the handle
    - `ensurePermission()` — re-requests read/write on reload (FSA requires this each session)
    - `list(path)` → `{ name, kind: 'file'|'dir', size? }[]`
    - `readFile(path)` → `string`
    - `writeFile(path, content)` — creates parents as needed
    - `createFile(path)`, `createDir(path)`, `remove(path)`, `rename(oldPath, newPath)`
    - `seed()` — on first connect, creates `Documents/`, `Pictures/`, `Downloads/`, `Welcome.txt`
    - `isNativeFSA` — boolean feature flag for UI
- **`fsa.ts`** — File System Access API implementation (Chromium). Walks directory handles by path segments; persists the root `FileSystemDirectoryHandle` in IndexedDB under `nd-os-web:workspace-handle` so it survives reloads.
- **`fallback.ts`** — IndexedDB-backed virtual filesystem. Object store `entries` keyed by path, each `{ path, kind, content? }`. Mirrors the same public API surface.
- **`detect.ts`** — `'showDirectoryPicker' in window` → native, else fallback.

### Path model
All consumer code (Files, Notes, Editor) uses POSIX-style string paths. Backends translate internally. This keeps the apps backend-agnostic.

### Migration
- On first workspace connect, migrate the existing `nd-os-web:notes` localStorage value into `/Notes.md` (if that file doesn't already exist).
- Seed `/Documents`, `/Pictures`, `/Downloads`, `/Welcome.txt` on first connect only.

## UI changes (all in `App.svelte` + `global.css`)

### 1. Workspace picker + status
- **Topbar**: small status pill after the clock — `🔌 Workspace: Native` (green) or `Workspace: Browser` (amber) or `Not connected` (grey). Click → opens Settings → Workspace section.
- **Settings → new "Workspace" section** (above Taskbar):
  - Connection status, backend type, entry count
  - **Connect workspace…** button (calls `connect()`)
  - **Disconnect** button (with confirm toast)
  - **Reveal in file manager** button (FSA only — `reveal()` if supported)
- **First-run prompt**: if user opens Files/Notes/Editor with no workspace, a centered modal explains "Pick a folder to store your files" with Connect / Use browser storage buttons.

### 2. Files app — real browser
Replace hardcoded placeholder cards (`App.svelte:977-994`) with:
- **Path bar / breadcrumbs**: `ND OS › Documents › Sub` — click any segment to navigate up
- **Entry list**: icons + names + sizes, double-click folder = navigate, double-click file = open in Text Editor
- **Toolbar**: ↑ (up), New File, New Folder, Rename, Delete (with confirm), and a "Connect workspace" button when disconnected
- Selection state, right-click → context actions (reuse existing context menu styling)
- Back/forward history (optional stretch)

### 3. Notes app — file-backed
- Reads from `/Notes.md` on mount (after hydration), writes back via debounced `writeFile('/Notes.md', notes)`.
- Falls back to localStorage if workspace not connected (keeps current behavior).
- Same textarea UX, just a different backend.

### 4. NEW: Text Editor app (`editor`)
- Catalog entry: `🅝 Text Editor` / "Edit workspace files"
- State: `currentPath`, `editorContent`, `editorDirty`
- Loads file via `readFile(path)`, saves via Cmd/Ctrl+S or auto-save with dirty indicator
- New file flow: prompt for path in workspace
- Recent files list (persisted in localStorage — small, config-like)
- Opened from Files app double-click; also reachable from dock/start/spotlight

### 5. Terminal — add workspace commands
Extend the existing mock shell with real workspace ops:
- `ls [path]`, `cat <path>`, `touch <path>`, `mkdir <path>`, `rm <path>`, `pwd`, `write <path> <text>`, `open <path>` (opens in editor)

## Tradeoffs / notes
- **FSA permission UX**: each new browser session requires a one-click re-grant. We persist the handle in IndexedDB so the folder doesn't have to be re-picked, only re-permissioned. The topbar pill shows when re-grant is needed.
- **No backend**: this is still a browser app — "real files" only on Chromium-family. Firefox/Safari users get transparent IndexedDB storage that behaves identically but stays browser-private.
- **Single file per app**: ND OS still opens one window per app id (existing constraint). Multi-window editor sessions are out of scope.
- **No binary files**: text only in this iteration (`.txt`, `.md`, `.json`, etc.). No image/blob handling yet.
